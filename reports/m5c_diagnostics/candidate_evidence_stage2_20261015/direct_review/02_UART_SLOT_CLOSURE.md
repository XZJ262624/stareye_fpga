# Non-preemptive diagnostic slot: bounded production contract

The original unresolved arbitration paragraph in BINDING_AND_TRANSPORT_DESIGN.md is historical. No normal cancellation or queued original-start implementation was introduced. The actual implementation prevents an original packet request during the admitted diagnostic interval; violating that contract triggers the named simulation assertion, rather than being certified as a supported input sequence.

Grant requires the real previous type4 completion, backend IDLE, no packet/start, no ready/take/pending telemetry, no reserve/capture/writer ownership, run and no stop. It also requires more than700000 UI clocks until the next scheduled background request and the early frame window. The production raster1650x750 at74.4MHz and UI96MHz gives1596774.19 UI clocks/frame; window age<896000 leaves at least700774 clocks, before accounting for the conservative margin. The real default460800 serializer measured675542 clocks per324B record. Bridge read settling is shorter than a UART byte; bounded stall tests are separate conditional tests, not a promise of unbounded consumer stalls within the production slot.

Original packet_start sources are: telemetry at the next completed frame (previous mailbox/build/ready already drained), and statistics/export/fault from a background transaction. A new transaction cannot start until the guarded request boundary; no older one is active at grant. Existing hard stop aborts the UART and diagnostic record before the original cold fault report. That case deliberately permits interrupted wire data and is not normal complete-stream or warm-recovery acceptance.

Actual enabled/disabled backend edge comparisons cover normal completion, insufficient request budget, closed frame window, deferred-to-next-frame service, and cold cancellation followed by the original fault report. A removed request guard produces DIAG_UNSAFE_GRANT; a removed frame window produces DIAG_SLOT_ORIGINAL_START_COLLISION. Both compiled successfully and hit exactly the named Fatal. The original positive implementation has no such collision. This is finite verification plus the stated production-clock scheduling argument, not exhaustive formal proof.

The default mixed test additionally compares original type1..4 UART output, payload-ready, busy and done every cycle against the fixed3b49 serializer. The interposed type5 and all four original256B payloads are checked as1620 exact wire bytes with full header/reserved/CRC. It does not substitute for full-size backend class/mask export or integrated DDR recovery regression.
