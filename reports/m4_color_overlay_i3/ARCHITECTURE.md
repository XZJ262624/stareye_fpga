# M4架构、坐标与流水线

基线：M3.2提交3424514afe1721dc000495673c0ca757ea1f6372的启用中值工程。官方projectdb创建69个输入文件的独立副本；新顶层和XML之外67个物理接口、PLL、SDC、DDR/FIFO及相机/HDMI输入逐字保持。新增四个M4 RTL；共享原median、Sobel、窗口和阈值核不修改。

源流由example_top内lcd_driver输出lcd_gray/lcd_de/lcd_hs/lcd_vs，使用clk_pixel/rstn_pixel，SOF为~lcd_vs。DDR读请求和反馈保持原样。实际像素PLL74.4MHz、1650×750光栅保持，名义720p60沿用已签收显示器识别；74.4MHz不改写成精确74.25MHz。所有新状态均在同一像素域，没有新增跨时钟控制路径。

M32原RAW对应slot(x,y)，Sobel对应中心(x−1,y−1)。仅给背景延迟而保持旧显示同步会留下坐标解释错误。M4将整个旧结果包统一延迟一行加一像素，所有模式共用同一DE/HS/VS；RAW/MAG/BIN只整体延后，像素内容保持原样。当前M32边缘中心必须等于延迟包的slot坐标，且有效、DE、滤波状态与阈值一致，才允许OVERLAY红色。

54位延迟包包含原RAW、原三模式结果、阈值、模式、滤波状态、DE/HS/VS和x/y。复用固定光栅RAM，DELAY=1650、深度1651；跨模块采样使原M32结果有效延后1651拍。新增映射11个RAM块，没有整帧缓存。

| 事件 | 原始中心像素在n采样后的时刻 |
|---|---|
| 原M32 slot输出 | n+1666 |
| M4统一光栅包及组合RGB | n+3317 |
| M4 RGB OSD与HDMI输入 | n+3318 |

最终RAW延迟3318拍，约44.597µs（74.4MHz）；相对M32最终显示1667拍增加1651拍。OVERLAY边缘由原中心后一行后一像素的样本在n+1651进入原链，n+3317产生，与同周期原中心背景相遇，OSD再一级。真实HDL四完整720p帧已核实延迟，不只按源码估算。

启用中值的OVERLAY完整支持域为中心2≤x≤1277、2≤y≤717；旁路为1≤x≤1278、1≤y≤718。其余有效图像仍显示原灰度但不红；无DE输出黑色。旧MAG/BIN保留M32槽位边界策略，不能把旧BIN的右下槽位显示习惯冒充OVERLAY中心坐标。

原三模式回归由独立M32实例及原M31 OSD逐像素比较，仅允许统一1651拍延迟。RAW和OVERLAY背景完全来自原始灰度，中值只作用于Sobel输入。新RGB选择模块输出RGB888：非边缘原灰度复制，合法边缘ff0000。厂商rgb2dvi实际低字节蓝/txd0、中字节绿/txd1、高字节红/txd2；1024组真实编码通道检查通过，未改HDMI IP。

固定1650拍、连续1280个DE像素协议保持。监视提前结束/超长DE及异常行周期，对坏帧OVERLAY红色关闭，下一VS帧边界恢复；旧三模式不因监视器改变。复位时RAM不清零，ready和valid防止历史像素泄漏。非法行内gap不是受支持的视频重锚协议；已测试坏帧关闭、异步复位及后续完整帧恢复，不能声称任意暂停仍保持整链路坐标。

新模块使用异步置复位、像素域同步释放；继承PLL LOCKED异步复位/失锁恢复、DDR电气/全容量压力与未约束外设I/O风险不关闭。
